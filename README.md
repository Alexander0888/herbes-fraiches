# Rayon 74 · Fruits et légumes

Единое приложение для сотрудников отдела овощей и фруктов. На главной расположены шесть карточек. Доступен **Herbes fraîches**; **Visite virtuelle**, **Analyse des déchets**, **Analyse des commandes**, **Contrôle des étiquettes** и **Promotions** отмечены **En développement** и пока не открываются.

Раздел трав помогает планировать выкладку свежих трав в отделе 74. Стенд состоит из 6 столбцов и 8 рядов. Нижний край **Côté client** обращён к покупателю. Стартовые шаблоны — **Journée normale** (36 заполненных ячеек) и **Forte demande** (48 заполненных ячеек). В новой базе применяется **Journée normale**.

## Запуск в VS Code

1. В VS Code выберите **File → Open Folder…** и откройте `/Users/rp/Code/herbes-fraiches` (на другом компьютере — свою папку этого репозитория).
2. Откройте **Terminal → New Terminal**. Используйте Node.js 22.12 или новее.
3. При первом запуске установите зависимости командой `npm ci`.
4. Запустите `npm run dev` и откройте [http://localhost:5173](http://localhost:5173). Если порт занят, Vite покажет другой адрес в терминале. Чтобы остановить сервер, нажмите **Ctrl+C**.

```sh
npm test
npm run build
npm run preview
```

Первая команда запускает проверки данных, вторая собирает приложение в `dist/`, третья показывает готовую сборку локально.

## Страницы и режимы хранения

- `/` или `#/` — главное меню; `#/herbs` — инструмент трав. Прямая ссылка на раздел работает и после обновления страницы. **Accueil** возвращает к меню.
- Маршруты через `#` обрабатывает React Router в браузере. GitHub Pages не требуется искать отдельный HTML-файл для каждого раздела.
- **Рабочий сайт с Supabase:** общая база, публичный просмотр применённой схемы, вход руководителя для редактирования. Сессия сохраняется при переходах между разделами.
- **Локальный демонстрационный режим:** если обе переменные Supabase пусты, используется `localStorage`, редактор доступен без входа. Данные остаются только в этом браузере и не синхронизируются. Обычный `npm run dev` использует этот режим при отсутствии настроек Supabase.
- **Локальный общий режим:** `npm run dev:shared` использует `.env.shared.local` и отдельный тестовый Supabase на этом компьютере.

## Как пользоваться разделом трав

- **Consultation** показывает применённую схему, время применения и количество мест для каждой травы.
- В **Éditeur** выберите шаблон, затем траву и касайтесь нужных ячеек. При открытии редактора ничего не выбрано. Повторное нажатие с той же выбранной травой освобождает ячейку. Чтобы очистить любую ячейку, выберите **Vider la case**.
- **Tout vider** очищает все ячейки текущего черновика после подтверждения.
- **Réinitialiser les modifications** возвращает имя и раскладку к последней сохранённой версии шаблона после подтверждения.
- **Enregistrer** сохраняет раскладку и изменённое имя в шаблоне.
- **Appliquer au présentoir** копирует текущую раскладку и имя из редактора в действующую схему. Чтобы сохранить эти же изменения для повторного использования, нажмите **Enregistrer**.
- **Dupliquer** создаёт новый шаблон на основе текущего состояния редактора. Копия и исходный шаблон сохраняются отдельно. Удаление шаблона сохраняет действующую схему до следующего применения.
- При несохранённых изменениях переход **Accueil**, «Назад» / «Вперёд» внутри приложения, смена шаблона, режима и выход требуют подтверждения. **Annuler** оставляет черновик. Во время сохранения переход ждёт завершения операции.
- Обновление или закрытие вкладки вызывает стандартное предупреждение браузера, если он поддерживает его в текущем сценарии. Черновик не сохраняется автоматически: перед закрытием приложения используйте **Enregistrer**.

## Общий режим на этом Mac

Общий режим использует локальный Supabase. Скрипт запускает PostgreSQL, Auth, API и Realtime через Supabase CLI. На Mac с Apple Silicon CLI выбирает нативный режим, если Docker или Podman недоступны. Первый запуск загружает компоненты Supabase и применяет миграции.

В терминале VS Code выполните:

```sh
npm ci
npm run db:start
npm run db:demo
npm run dev:shared
```

Откройте [http://localhost:5174](http://localhost:5174/). Откройте карточку **Herbes fraîches** или прямую ссылку [http://localhost:5174/#/herbs](http://localhost:5174/#/herbs). Для проверки редактора нажмите **Se connecter** и возьмите email и пароль роли `manager` из файла `supabase/demo-accounts.local` в VS Code. Миграции создают два стартовых шаблона для пустой базы. Скрипт создаёт тестовые учётные записи и локальные настройки `.env.shared.local`. Оба локальных файла исключены из Git. Для браузера используется только публикуемый ключ Supabase.

- **manager** — открывает **Éditeur**, редактирует шаблоны и применяет снимок схемы. Если тот же шаблон уже обновил другой руководитель, база отклонит сохранение поверх новой версии. Скопируйте черновик через **Dupliquer** и обновите страницу, чтобы открыть свежие версии шаблонов.
- **Посетитель по ссылке на раздел трав** сразу видит действующую схему. Чтобы проверить автоматическое обновление, откройте вторую сессию браузера без входа и нажмите **Appliquer au présentoir** в сессии руководителя. Тестовая роль **employee** нужна для проверки того, что обычный аккаунт не получает прав редактора.
- При потере связи открытая страница показывает последний загруженный план. После восстановления она запрашивает актуальную схему. Для проверки можно остановить и снова запустить локальную базу, оставив вкладку сотрудника открытой.

```sh
npm run test:shared
npm run build -- --mode shared
npm run db:stop
```

`npm run test:shared` проверяет права и сохранение шаблонов через локальный API. Выполняйте команду, пока работает Supabase и создана тестовая схема. Обычный `npm run dev` на порту 5173 по-прежнему открывает версию с `localStorage`. Её шаблоны доступны в прежнем браузере по прежнему адресу. Общий режим начинает с двух стартовых шаблонов в собственной базе.

## Где находится код общего режима

- `supabase/migrations/` — структура базы, права на уровне строк (RLS) и команда публикации.
- `src/features/herbs/data/sharedPlanStore.js` — запросы к Supabase и подписка на изменения действующей схемы.
- `src/services/SharedAccess.jsx` — вход и проверка роли.
- `scripts/setup-local.js` — подготовка тестовой базы и учётных записей.

Текущие правила открывают чтение действующей схемы без входа. База разрешает изменять шаблоны и публиковать схему только роли руководителя отдела 74. Для проверки на физических устройствах понадобится один сервер Supabase, доступный обоим устройствам.

Документация: [локальный Supabase](https://supabase.com/docs/guides/local-development), [права RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Realtime](https://supabase.com/docs/guides/realtime/postgres-changes).

## Проверки

```sh
npm test
npm run build
npx playwright install chromium webkit
npm run test:ui
```

Браузерные тесты запускают отдельный Vite на порту 5181 и используют изолированные профили без пользовательских данных. Проверяются главное меню, прямые ссылки, перезагрузка, история браузера, защита черновика, операции с шаблонами и сетка 6×8. Размеры: телефон 390 px, iPad mini 768 px, большой планшет 1024 px, компьютер 1440 px; дополнительно проверяется ширина 320 px. Это эмуляция в Chromium/WebKit, а не проверка на физических устройствах.

При работающем локальном Supabase и подготовленных тестовых аккаунтах:

```sh
npm run test:shared
npm run test:ui:shared
```

`test:shared` берёт адрес из `.env.shared.local`, поэтому может использовать уже запущенную локальную базу после смены Git-ветки. `test:ui:shared` проверяет вход, сессию между страницами, выход с черновиком, обновление в отдельном публичном браузере и ошибку сохранения во время перехода. Он создаёт временные шаблоны, временно применяет тестовый план, затем удаляет шаблоны и восстанавливает прежнее имя и раскладку. Время применения в локальной базе обновится. Оба набора отказываются работать с адресом облачного Supabase. Учётные данные читаются из игнорируемого файла; запись трассировки входа отключена.

На реальных устройствах дополнительно проверьте нажатия пальцем, экранную клавиатуру, поворот экрана, возврат из фонового режима и восстановление связи.

## Разработка и публикация

Заметные изменения делаем в отдельной ветке. Обновление `main` запускает публикацию через GitHub Actions; локальные изменения и рабочая ветка сами по себе сайт не обновляют. Текущее расширение меню не требует новых миграций и не меняет облачные шаблоны.

Откройте [главное меню Rayon 74](https://alexander0888.github.io/rayon-74/) или сразу [схему стенда Herbes fraîches](https://alexander0888.github.io/rayon-74/#/herbs). Исходный код хранится в [репозитории rayon-74](https://github.com/Alexander0888/rayon-74).

## Публикация на GitHub Pages

GitHub Pages раздаёт файлы интерфейса. Для входа менеджера, хранения шаблонов и обновления схемы используется отдельный облачный проект Supabase.

Следующие шаги нужны для новой установки; для существующего рабочего проекта повторно создавать базу и аккаунты не нужно.

1. Создайте проект в [Supabase](https://supabase.com/dashboard) и примените SQL-файлы из `supabase/migrations/` по порядку. Через Supabase CLI это можно сделать командой `npx supabase db push --remote` после привязки проекта командой `npx supabase link --project-ref PROJECT_REF`. На пустой базе миграции создают два шаблона и применяют **Journée normale**. Локальные пользовательские шаблоны в облако автоматически не переносятся.
2. В **Authentication → Users** создайте рабочий аккаунт менеджера. В настройках Auth отключите самостоятельную регистрацию. В SQL Editor выдайте аккаунту роль руководителя, подставив его UUID из списка пользователей:

   ```sql
   insert into public.rayon_members (user_id, role)
   values ('MANAGER_USER_UUID', 'manager');
   ```

3. В репозитории GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте `VITE_SUPABASE_URL` с HTTPS-адресом облачного проекта и `VITE_SUPABASE_PUBLISHABLE_KEY` с ключом `sb_publishable_…`. Этот ключ предназначен для браузера. Пароли менеджеров, ключи `sb_secret_…` и строки подключения к базе остаются вне GitHub и сборки. Локальный файл `supabase/demo-accounts.local` исключён из Git.
4. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**. Вкладка **Actions** позволяет запустить **Deploy Herbes fraîches to Pages** вручную после настройки. Дальше он запускается при обновлении ветки `main`. После успешной публикации ссылка видна в **Settings → Pages**.
5. Проверьте ссылку в браузере без входа и на телефоне. В другой сессии войдите менеджером и примените схему. Телефон должен обновить раскладку без перезагрузки.

[GitHub Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) · [Ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys)
